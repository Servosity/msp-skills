# governance-snapshot

Turn the read-only `microsoft-graph-cli apps consent` command into a
white-labelable **third-party app consent** governance report an MSP can run for
any Microsoft 365 tenant and hand to the client.

This is a **playground** - a packaging + go-to-market experiment on top of the
shipped `microsoft-graph` skill. The CLI command it depends on is the real,
tested, published one; everything here is the report layer, the kit, and the
first-real-run harness.

## What's here

| Path | What it is |
| --- | --- |
| `report.py` | The report engine. Renders `apps consent --json` into a Markdown governance report. Demo-mode + white-label + sanitize. |
| `samples/demo-consent-audit.json` | Synthetic, **shape-accurate** sample (generated by running the real `ConsentAudit` over clearly-fake vendors: Acme, Contoso, Fabrikam). |
| `samples/demo-report.md` | The demo report rendered from that sample. |
| `kit/report-template.md` | White-label shell an MSP brands and wraps around the generated findings. |
| `kit/sample-shareable-report.md` | Sanitized (vendor names redacted) shareable sample - safe to show a prospect. |
| `drafts/one-pager-msp.md` | DRAFT internal one-pager: the MSP play. |
| `drafts/one-pager-client.md` | DRAFT client-facing leave-behind one-pager. |
| `scripts/first-real-run.sh` | Armed harness: generates the FIRST real report against Servosity's tenant once a token exists, proves it's not canned, embeds receipts. |
| `NEEDS-DAMIEN-auth.md` | The one 10-minute auth needed to arm the first real run. |
| `test_report.py` | Runnable self-check for `report.py`. |

## Try demo-mode now (no auth, no tenant)

```bash
python3 report.py --demo                       # print the synthetic report
python3 report.py --demo --org "Acme Dental"   # white-labeled header
python3 report.py --demo --sanitize            # vendor names redacted (shareable)
python3 test_report.py                         # self-check
```

Demo-mode reads `samples/demo-consent-audit.json` - **synthetic data**, clearly-fake
vendors. It is the exact JSON shape the real command emits, so demo-mode and real-mode
run the identical renderer; the only difference is the JSON on the way in. That is the
design: the report is always computed, never canned.

## Generate the first REAL report

Do the one-time read-only auth in [`NEEDS-DAMIEN-auth.md`](./NEEDS-DAMIEN-auth.md), then:

```bash
./scripts/first-real-run.sh
```

Until that auth happens, the script stops cleanly at the auth boundary and **no live
report exists**. Run `./scripts/first-real-run.sh --dry-run` to see the boundary now.

## How the demo sample was made (reproducible)

The sample is not hand-written JSON that could drift from the code. It was produced by
running the shipped `insights.ConsentAudit` function over synthetic service-principal /
grant / app-role rows. If the command's output shape ever changes, regenerate the sample
the same way rather than editing it by hand - hand-edited findings are how a governance
report becomes a lie.
